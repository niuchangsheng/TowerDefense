# 三国五行塔防 - 产品需求文档 (PRD)

## 问题陈述

用户希望开发一款结合三国历史文化与中国五行元素的塔防游戏。市面上现有塔防游戏大多缺乏中国文化特色，且RPG成长元素与塔防结合不够深入。用户需要一个能够：

- 体验三国历史战役的沉浸感
- 利用五行相生相克策略进行深度玩法
- 通过英雄收集和装备系统获得长期成长动力
- 在无商业化压力的纯单机环境下享受游戏

---

## 解决方案

开发一款基于 Phaser 3 + TypeScript 的三国五行塔防游戏，融合传统塔防玩法与RPG成长系统：

- **核心玩法**：传统塔防模式，玩家放置三国英雄防守敌人进攻
- **五行系统**：英雄五行属性克制敌人（相克），宝石激活神器（相生）
- **RPG成长**：英雄通过魂石解锁/升星，等级提升，装备强化
- **关卡设计**：章节式主线重现历史战役 + 番外关卡提供变数
- **纯单机体验**：无体力限制、无商店、无社交，所有内容通过关卡进度获取

## 用户故事

### 核心玩法

1. 作为玩家，我希望在战场上放置英雄来防守敌人的波次攻击，以便保护我的基地不被突破
2. 作为玩家，我希望英雄自动攻击范围内的敌人，以便我可以专注于战略布局而非微操
3. 作为玩家，我希望在关键时刻手动触发英雄的主动技能，以便我能精确应对危急情况
4. 作为玩家，我希望主动技能可以切换为自动释放模式，以便在需要时享受更轻松的游戏体验
5. 作为玩家，我希望敌人沿着预定义路径向我的基地移动，以便我可以在关键位置战略性地部署英雄
6. 作为玩家，我希望当敌人到达出口时看到剩余生命值减少，以便我理解防守的紧迫性
7. 作为玩家，我希望当生命值归零时游戏结束，以便我有一个明确的失败条件需要避免

### 五行系统

8. 作为玩家，我希望清晰地看到每个英雄的五行属性，以便我做出明智的部署决策
9. 作为玩家，我希望拥有正确五行属性的英雄对被克制的敌人造成额外伤害，以便战略性英雄选择得到奖励
10. 作为玩家，我希望在每个关卡面对混合五行属性的敌人，以便我必须部署多样化的英雄团队
11. 作为玩家，我希望将特定五行属性的宝石装备到英雄的神器上，以便通过五行相生激活特殊效果
12. 作为玩家，我希望看到激活的神器效果在视觉上有明显区分，以便我知道哪些加成已生效

### 英雄系统

13. 作为玩家，我希望通过击败关卡敌人和Boss收集英雄魂石，以便每场战斗都有明确目标
14. 作为玩家，我希望通过合成收集的魂石解锁新英雄，以便我的努力带来进展感
15. 作为玩家，我希望通过收集更多魂石提升英雄的星级，以便我的英雄随时间变得更强
16. 作为玩家，我希望英雄通过战斗获得经验并升级，以便我看到持续的成长
17. 作为玩家，我希望看到英雄的攻击力、攻击速度和攻击范围属性，以便我理解他们的战斗定位
18. 作为玩家，我希望不同英雄有不同的部署费用，以便我必须平衡实力与经济
19. 作为玩家，我希望每个英雄有独特的被动技能，以便即使同一五行的英雄也有区别
20. 作为玩家，我希望每个英雄有独特的主动技能，以便我能在战斗中做出战术决策
21. 作为玩家，我希望在MVP版本中看到10-15个英雄阵容，以便我有足够的多样性而不会过于复杂

### 装备系统

22. 作为玩家，我希望通过完成关卡获得装备，以便除英雄成长外还有其他奖励
23. 作为玩家，我希望装备武器来提升英雄的攻击力，以便我可以自定义英雄配置
24. 作为玩家，我希望装备带有宝石槽的神器，以便我可以解锁特殊效果
25. 作为玩家，我希望通过完成关卡获得宝石，以便我可以收集神器激活所需的资源
26. 作为玩家，我希望将3个低级宝石合成为1个高级宝石，以便我可以升级我的资源
27. 作为玩家，我希望将五行宝石嵌入神器以激活其特殊效果，以便相生系统有游戏意义
28. 作为玩家，我希望看到每个神器需要哪种五行宝石，以便我知道该收集什么

### 费用系统

29. 作为玩家，我希望每个关卡开始时有固定的部署费用，以便我有初始英雄部署的基础
30. 作为玩家，我希望通过击杀敌人获得部署费用，以便我可以随时间扩展我的防线
31. 作为玩家，我希望击杀精英敌人和Boss获得额外部署费用，以便困难敌人带来奖励
32. 作为玩家，我希望撤退英雄时回收部分部署费用，以便我可以战略性地重新部署防线
33. 作为玩家，我希望不同英雄根据实力有不同的部署费用，以便强力英雄不是免费可用的

### 关卡系统

34. 作为玩家，我希望在MVP中体验3个主线章节，以便我体验核心叙事弧线
35. 作为玩家，我希望每章有5个关卡（共15关），以便我有足够的内容推进
36. 作为玩家，我希望章节代表三国历史事件（黄巾之乱、讨伐董卓、官渡之战），以便我沉浸在历史主题中
37. 作为玩家，我希望解锁2-3个番外关卡，以便我可以探索替代场景并获得特殊奖励
38. 作为玩家，我希望按顺序推进关卡，以便难度适当递增
39. 作为玩家，我希望可以重玩已完成的关卡，以便我可以刷魂石和装备

### 敌人系统

40. 作为玩家，我希望面对不同五行属性的大量普通敌人波次，以便我必须调整英雄组合
41. 作为玩家，我希望遇到有特殊能力的精英敌人，以便战斗除了数量外还有多样性
42. 作为玩家，我希望面对只能被远程英雄攻击的飞行敌人，以便英雄攻击范围有意义
43. 作为玩家，我希望遇到移动快速的高速敌人，以便我必须提前规划防守
44. 作为玩家，我希望面对需要高攻击力的高防御敌人，以便英雄属性有区分
45. 作为玩家，我希望遇到死亡时造成范围伤害的自爆敌人，以便我必须考虑站位
46. 作为玩家，我希望每章结束时面对Boss敌人，以便我有高潮战斗

### 游戏模式

47. 作为玩家，我希望体验无体力/耐力限制的纯单机游戏，以便我想玩多久就玩多久
48. 作为玩家，我希望游戏中没有商店，以便进展完全基于技能和努力
49. 作为玩家，我希望没有多人或社交功能，以便我可以专注于自己的旅程
50. 作为玩家，我希望所有内容都可通过游戏解锁，以便我的努力得到奖励

### UI/UX

51. 作为玩家，我希望每个关卡前看到英雄选择面板，以便我可以规划团队组成
52. 作为玩家，我希望战斗中实时看到英雄部署费用，以便我知道何时可以放置更多英雄
53. 作为玩家，我希望看到敌人血条，以便我了解战斗进展
54. 作为玩家，我希望看到波次指示器，以便我知道下一波何时到来
55. 作为玩家，我希望在英雄和敌人上清晰看到五行图标，以便我可以快速识别克制关系
56. 作为玩家，我希望每个已部署英雄有撤退按钮，以便我可以回收费用并重新部署
57. 作为玩家，我希望看到技能冷却计时器，以便我知道主动技能何时可用
58. 作为玩家，我希望可以切换主动技能的自动释放，以便我可以选择我的参与程度
59. 作为玩家，我希望胜利/失败画面显示奖励，以便我看到我获得了什么
60. 作为玩家，我希望英雄详情页面显示属性、技能和装备，以便我可以管理我的阵容
61. 作为玩家，我希望有装备管理界面，以便我可以优化英雄配置
62. 作为玩家，我希望有宝石合成界面，以便我可以升级我的宝石
63. 作为玩家，我希望有关卡选择地图，以便我可以导航章节和关卡
64. 作为玩家，我希望每个英雄有魂石进度指示器，以便我知道离解锁/升级还有多远

## 实现决策

### 技术架构

- **游戏引擎**：Phaser 3，用于2D游戏渲染和物理
- **开发语言**：TypeScript，提供类型安全和可维护性
- **运行平台**：基于浏览器（Web），后续可打包为独立可执行文件
- **状态管理**：分离游戏状态与渲染状态，实现清晰架构

### 核心模块划分

#### 深层模块（高内聚，简单接口）

1. **战斗系统模块 (Battle System Module)**
   - 接口：`startBattle(levelConfig)`、`placeHero(heroId, position)`、`retreatHero(heroId)`、`triggerSkill(heroId)`、`update(dt)`
   - 封装：敌人波次生成、英雄攻击逻辑、伤害计算、五行克制倍率、费用系统、胜负判定

2. **英雄管理模块 (Hero Management Module)**
   - 接口：`getHero(heroId)`、`unlockHero(heroId, soulStones)`、`upgradeStar(heroId, soulStones)`、`levelUp(heroId, exp)`、`equipItem(heroId, itemId, slot)`、`socketGem(heroId, artifactId, gemId)`
   - 封装：英雄属性、等级成长、星级成长、装备槽位、技能定义

3. **关卡配置模块 (Level Config Module)**
   - 接口：`getLevel(levelId)`、`getChapter(chapterId)`、`getChapterProgress()`、`unlockLevel(levelId)`
   - 封装：关卡定义、敌人波次配置、Boss配置、奖励表、解锁条件

4. **库存模块 (Inventory Module)**
   - 接口：`getSoulStones(heroId)`、`addSoulStones(heroId, amount)`、`getEquipment(itemId)`、`addEquipment(itemId)`、`getGem(gemId)`、`addGem(gemId)`、`synthesizeGem(lowGemIds)`
   - 封装：魂石计数、装备存储、宝石存储、合成规则

5. **存档系统模块 (Save System Module)**
   - 接口：`saveGame()`、`loadGame()`、`resetGame()`
   - 封装：所有玩家进展的序列化/反序列化、localStorage或文件持久化

#### 浅层模块（协调性模块）

6. **UI控制器模块 (UI Controller Module)**
   - 协调：战斗UI、英雄面板、装备界面、关卡地图、奖励画面
   - 依赖：战斗系统、英雄管理、库存模块

7. **场景管理模块 (Scene Manager Module)**
   - 协调：Phaser场景切换（标题、关卡选择、战斗、英雄管理、装备）
   - 依赖：Phaser场景API

### 五行系统数值设计

- **克制倍率**：英雄克制敌人时，伤害倍率 = 1.5倍
- **五行相生映射**：金→水→木→火→土→金（循环）
- **宝石激活规则**：宝石的五行属性必须"生"神器的五行属性才能激活

### 英雄属性模型

```
英雄 {
  id: 字符串
  name: 字符串
  wuXing: '金' | '木' | '水' | '火' | '土'
  rarity: '普通' | '稀有' | '史诗' | '传说'

  // 基础属性
  baseAttack: 数值
  baseAttackSpeed: 数值  // 每秒攻击次数
  baseAttackRange: 数值  // 游戏单位
  deploymentCost: 数值

  // 成长属性
  level: 数值 (1-60)
  star: 数值 (1-5)
  experience: 数值

  // 技能
  passiveSkill: 技能
  activeSkill: 技能

  // 装备
  weaponSlot: 装备 | 空
  artifactSlot: 神器 | 空
}
```

### 敌人属性模型

```
敌人 {
  id: 字符串
  name: 字符串
  wuXing: '金' | '木' | '水' | '火' | '土'
  type: '普通' | '精英' | 'boss' | '飞行' | '高速' | '高防' | '自爆'

  health: 数值
  speed: 数值
  rewardCost: 数值  // 击杀时给予玩家的部署费用
  dropTable: 掉落物品[]
}
```

### 装备属性模型

```
装备 {
  id: 字符串
  name: 字符串
  type: '武器' | '神器'
  rarity: '普通' | '稀有' | '史诗' | '传说'

  bonuses: {
    attack?: 数值
    attackSpeed?: 数值
    attackRange?: 数值
  }

  // 神器专用
  gemSocket?: {
    requiredWuXing: '金' | '木' | '水' | '火' | '土'
    currentGem: 宝石 | 空
  }
  activatedEffect?: 技能效果
}

宝石 {
  id: 字符串
  wuXing: '金' | '木' | '水' | '火' | '土'
  level: 数值 (1-5)
}
```

### 关卡结构模型

```
关卡 {
  id: 字符串
  chapterId: 字符串
  name: 字符串
  type: '主线' | '番外'

  mapConfig: {
    path: 点[]  // 敌人移动路径
    spawnPoint: 点
    exitPoint: 点
    deployableAreas: 区域[]
  }

  waves: 波次配置[]
  boss?: 敌人配置

  rewards: {
    soulStones?: { heroId: 字符串, amount: 数值 }
    equipment?: 装备配置[]
    gems?: 宝石配置[]
    gold?: 数值
  }

  unlockCondition?: 字符串  // 前一关卡ID，首个关卡为空
}

章节 {
  id: 字符串
  name: 字符串
  historicalEvent: 字符串  // 如"黄巾之乱"
  levels: 关卡[]
  sideLevels?: 关卡[]
}
```

### 战斗费用系统

- **初始费用**：20点
- **普通敌人击杀奖励**：+1点
- **精英敌人击杀奖励**：+3点
- **Boss击杀奖励**：+10点
- **撤退返还**：50%部署费用

### MVP内容规模

- **英雄数量**：10-15个，每个五行2-3个
- **主线关卡**：3章 × 5关 = 15关
- **番外关卡**：2-3个
- **章节主题**：
  - 第一章：黄巾之乱
  - 第二章：讨伐董卓
  - 第三章：官渡之战

## 测试决策

### 测试原则

- 只测试外部行为，不测试实现细节
- 使用模拟数据验证系统逻辑
- 分离单元测试和集成测试

### 需要测试的模块

1. **战斗系统模块**
   - 测试：英雄放置逻辑、费用消耗、撤退返还计算
   - 测试：克制伤害倍率计算
   - 测试：敌人波次生成
   - 测试：胜利/失败条件判定

2. **英雄管理模块**
   - 测试：英雄解锁条件（魂石数量）
   - 测试：升星数值增长
   - 测试：升级经验需求
   - 测试：装备属性叠加计算

3. **库存模块**
   - 测试：宝石合成规则（3低→1高）
   - 测试：魂石计数和消耗
   - 测试：装备/宝石获取

4. **关卡配置模块**
   - 测试：关卡解锁逻辑
   - 测试：章节进度追踪

5. **五行系统逻辑**
   - 测试：相克关系
   - 测试：相生关系
   - 测试：克制伤害计算

### 测试工具

- Jest 或 Vitest 作为测试框架
- 独立的测试数据文件，与游戏数据分离

## 范围外内容

以下内容不在MVP范围内：

- **体力/耐力系统**：玩家可无限游玩
- **商店系统**：无金币购买装备/宝石
- **抽卡系统**：无随机获取英雄机制
- **社交系统**：无好友、公会、排行榜
- **多人模式**：无合作或竞技玩法
- **音乐音效**：MVP版本暂不实现完整音效系统
- **动画特效**：基础动画足够，暂不实现高级特效
- **移动端适配**：MVP仅针对PC浏览器
- **存档云同步**：仅本地存档

## 其他说明

### 开发优先级建议

1. **阶段1 - 核心战斗系统**
   - 战斗系统模块基础实现
   - 英雄放置、攻击、撤退
   - 敌人波次生成
   - 费用系统

2. **阶段2 - 英雄与五行**
   - 英雄管理模块
   - 五行克制实现
   - 英雄技能系统

3. **阶段3 - 成长系统**
   - 库存模块
   - 英雄升级/升星
   - 装备系统
   - 宝石合成

4. **阶段4 - 关卡内容**
   - 关卡配置模块
   - 15关主线设计
   - 番外关卡
   - 敌人配置

5. **阶段5 - UI完善**
   - UI控制器模块
   - 英雄管理界面
   - 装备界面
   - 关卡选择地图

6. **阶段6 - 存档与优化**
   - 存档系统模块
   - 性能优化
   - 平衡性调整

### 美术风格建议

- 采用水墨风格或像素风格，契合三国主题
- 五行元素使用传统中国色彩（金-白、木-青、水-黑、火-红、土-黄）
- 英雄设计参考三国演义经典形象

### 后续迭代方向

- 增加更多章节（赤壁之战、三国鼎立等）
- 增加更多英雄（目标30+）
- 增加"无尽模式"
- 增加难度选择
- 考虑移动端适配
- 考虑音效音乐系统
